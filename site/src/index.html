What this is

One definition, vendored — not four copies

This layer lived in four repositories at once and had already begun to fork. It now lives here, and each consuming site copies the files it needs behind a brand.lock hash guard that fails its own CI offline. The page you are reading is drawn by those same files — every swatch below is painted by the variable it names, and the mark in the header is beating on the real rule. A wrong value renders as a wrong page.

The division of labour in the wordmark. Bank is what accumulates — the record of appreciation. Heart is what circulates — the value itself.

Take it. The token architecture, the derivation machinery and the theme cascade are Apache-2.0 and published for exactly this. On npm:

The mark is not covered: Apache-2.0 §6 grants no trademark rights and none are granted here. Copying emblem.svg conveys the path data, never the right to use the B-Emblem™ as a mark.

Institution repos vendor this layer; they do not install it. A dependency range is drift with a number on it, and the guard above only fires on files that are actually present. The package is a read-only mirror for everyone else.

The mark

B-Emblem™

A universal heart rotated 45° clockwise. It is bistable — heart and capital B, both immediately apparent. Not a reveal like the FedEx arrow; there is no aha to wait for, which is why it survives down to a 16px favicon.

  • Inline it in the DOM. Never <img src> — CSS cannot reach inside an <img>, so the colour would have to be duplicated everywhere the mark appears.
  • The 45° rotation is baked into the path coordinates. It used to be a transform attribute, which is a trap: a CSS animation on transform overrides a non-animated one, so the first heartbeat silently un-rotates the mark and it stops reading as a B.
  • fill="currentColor", and the page sets --emblem. There is no second colour to keep in step.
  • Never re-apply a rotation, and never scale the mark inside an icon canvas to "fix" padding — the maskable safe area was measured against the mark at its shipped size.

Motion

The heartbeat is a signal, not decoration

Two unequal beats and then a long rest — systole, a weaker diastole, then most of the period at rest. That morphology is what a counterfeit gets wrong at any tempo, which is why the rhythm is the signature and the rate is not. A 72 BPM variant was built and rejected.

Placement, not taste. .beating goes on chrome — a wordmark, a footer attribution, anything that says an institution stands behind this page. It goes never on a mark drawn beside somebody's name, where an unverified pulse would be claiming something about them.

Under prefers-reduced-motion: stop, and substitute nothing. The static mark is already a meaningful state, so there is no degradation to compensate for.

Colour

The B-Gem palette

A colour here means a medium. Ruby is video; fire opal is voice. The order is the Metta Light descent — session start at ruby, session end at diamond.

This is a media-type map, not a site palette. Using a gem as a site accent is only correct where the gem is that product's medium.

There are three palettes, and the other two are below. A gem means a medium; an aura stop means a rate; a rainbow hue means a domain. Seven, seven and six. The hues rhyme because a colour wheel is small — the meanings do not, and no two of them may ever be presented as one system.

Colour · in motion

The Metta Light

The gem order above is not a list — it is a descent. A session starts at ruby and ends at diamond, and the whole API is one number: the app sets --t from 0 to 1, and everything downstream reads --metta and never learns there was a number.

dev harness — never a product surface

No numerals, no totals, no streaks, no ranks. The light carries the whole signal. --t is an input, never a readout — rendering it as “42%” puts metering back into a surface built to have none. The readout beside the slider exists because this page documents the mechanism; a product surface shows the light and nothing else.

This is not an animated custom property, and that is the point. The obvious build — and the one the original reference for this uses — registers --metta with @property and interpolates it with @keyframes. This repo has already been burned by exactly that: Chrome does not reliably re-rasterise an element for an animated custom property it inherits, and the failure is invisible to getComputedStyle. Inheritance is not incidental here — it is the design — so that build is broken in the one configuration the feature requires.

So the ramp computes a plain value instead of animating one: six color-mix() steps, each weighted by a clamp() window off --t. No registration, no keyframes, no animation engine, no JS ticker. There is no enforcer to forget.

The chain lives on a class, not :root. Custom properties inherit their computed value, so a chain declared on :root resolves once against root's own --t and every descendant inherits the finished colour — the ramp goes dead and throws no error. The element that sets --t must be the element that carries the chain. Put .metta on the session container.

Breath, not heartbeat. The lamp's swell is a slow symmetrical breath with no claim attached. The heartbeat in motion.css is a Proof-of-Humanity signal with a placement rule. Never give the lamp .beating, and never give a mark the breath. Under reduced motion the breath stops and the colour does not — the descent is the session's real state, and freezing it would misreport where the sitter actually is.

Colour · second palette

The aura ramp

A colour here means a position — how fast a person's gratitude is circulating, measured as crossings per month and bucketed server-side. Not a medium, not a domain. A rate.

Extracted, not invented. These seven were typed by hand in three files of the shipping Phase-1 app, and all three still agreed when they were lifted — the pre-drift state this package exists to end, caught before it diverged. Nothing here was chosen; it was moved.

Seven stops here and seven gems above are different sets. This ramp carries indigo and ends at violet; the gems carry no indigo and end at the unrefracted diamond. The shared count is a coincidence.

And this ramp is discrete. A person sits in exactly one stop and never between two, which is why seven flat tokens are the right shape. The Metta Light — the gem order named above — is the continuous one, driven by a single scalar. Do not build this one as a gradient.

Two of these hexes collide with tokens declared elsewhere in the layer: --color-aura-red is byte-identical to --danger, and --color-aura-violet to --color-violet-sey. Coincidence, not kinship — three names, three meanings. Do not alias them, or re-tuning one will silently move the others.

Colour · third palette

The six-TLD rainbow

A colour here means a domain — one HeartBank® TLD, its product class, and the heart-idiom it was named for. The six were assigned one at a time, per domain; that they compose a complete rainbow was found afterwards, and that is the whole reason the allusion is earned rather than contrived.

TLD Hue Product class Heart-idiom

No value is pinned, and none is faked. The corpus fixes six colour words; no file in the estate fixes a hex. So the marks above are painted with the CSS keyword that spells the doctrine's word — a rendering of the name, never a value — which is why they look untuned beside the measured gems. They are supposed to.

Do not add six tokens to make that go away. Nothing consumes them: not one of the four sites vendoring this layer is a heartbank.{TLD}. Pin them when the first one needs them, and measure contrast then.

Why marks and not chips. These six hues are one-for-one with the six saturated gems. Two chip grids of the same six hues on one page read as one system no matter what the caption says, so the carrier changes with the meaning: a medium is a chip, a domain is a mark. Colour is a property of the emblem here, which is also what the doctrine says an aura is.

This palette is body-scoped, in a way the other two are not — it belongs to HeartBank®, one body of five. It is documented here because this is where the three palettes are told apart, not because the institution's colour system is one body's domain map.

The rule

A site's accent is derived, never picked

Each site takes the gem whose media type is that product's medium. Everything else — the whole alpha family — then falls out of one color-mix() chain.

Site Accent Because

Two values cannot derive, and that is the honest limit. --accent-ink is decided by contrast: Fire Opal on white is 3.4:1 and fails, Sapphire on white is 7.0:1 and passes, so one site takes near-black ink on its fill and another takes white. No formula picks correctly. On a light ground --accent-soft often needs pinning too. The goal was "a fifth site is five declarations"; it is nine.

Do not build a "pass a gem, get a theme" API. The true shape is a gem plus two measured overrides.

How to consume it

Vendor the files; the lock does the rest

There is no package to install and nothing to fetch at build time. A consumer copies the files it needs, copies brand.lock verbatim, and declares what it took in brand.uses — the one file in the set that differs per repository. 

# take the current layer
npm run brand:sync -- --from ../../333.eco/brand.333.eco

# in CI — no network, no credentials, no sibling checkout
npm run check:brand

Concatenation order

It is not arbitrary. Custom-property substitution is lazy, so a value declared early may reference one a later file sets — which is how --accent, set per site, reaches the derived family. 

tokens.css
  + theme-3block.css   or   theme-2state.css
  + motion.css
  + metta.css          opt-in — only where a session descends
  + reduce-global.css  (opt-in)
  + brand.css          (per site)
  + site.css           (per site)

Never @import a sibling of these files. The partial-based sites inject their stylesheets as raw text and concatenate them; a relative @import resolves against src/, where partials/ is unreachable, and ships a dead render-blocking at-rule that quietly destroys the one-request-renders-complete property.

Two theme files, on purpose

theme-3block.css is a dark-default cascade for sites that stamp both classes and must resolve the unstamped case themselves. theme-2state.css is a light-default stamp for a site whose resolver already handles three states and writes only .dark. Neither is the inferior variant of the other, and converting a site between them is a regression, not a tidy-up.
